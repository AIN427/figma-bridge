# figma-bridge

Локальный HTTP-сервер, через который ИИ-агент сам читает макеты из Figma — вместо того
чтобы вы руками выгружали JSON и перекидывали его в чат.

Ноль зависимостей. Только Node.js и личный токен Figma на чтение.

---

## Зачем

Если вы отдаёте макеты ИИ-агенту, вы знаете этот цикл: открыть Figma, выделить фрейм,
выгрузить, скопировать, вставить в чат, и так на каждый экран. А если выгрузить страницу
целиком — контекст кончится раньше, чем агент дойдёт до дела.

Цифры с живого проекта: файл из трёх страниц, 1138 экранов на главной. Его полный JSON —
**167 МБ**, это примерно **42 миллиона токенов**. В контекст не влезет никогда.

Через этот сервер тот же путь — «какие есть страницы → найти нужный экран → посмотреть
картинку → разобрать структуру → забрать все строки» — стоит **около 5,7 КБ**:

| Шаг | Ответ |
|---|---|
| `/f/:key` — весь файл в трёх строках | 192 Б |
| `/f/:key/screens?q=subscri` — нашлось 23 экрана | 1114 Б |
| `/f/:key/screen/:node?depth=3` — структура | 1225 Б |
| `/f/:key/screen/:node?detail=style` — цвета и стили | 824 Б |
| `/f/:key/text?screen=:node` — все 31 строка экрана | 2187 Б |
| `/f/:key/render?ids=:node` — путь к PNG на диске | 124 Б |

Разница не в сжатии, а в том, что агент спускается по уровням и берёт ровно нужное.

## Что умеет

- **Навигация по файлу** — страницы, экраны, поиск по имени и по тексту на экране.
- **Настраиваемая детализация** — от голого дерева имён до полного описания со стилями,
  авто-лейаутом и текстом.
- **Экспорт** — PNG для сверки глазами, SVG для иконок (дальше в VectorDrawable, в React-
  компонент, куда угодно). Файлы кладутся на диск, в ответе — путь, а не содержимое.
- **Реестр файлов** — свой индекс проектов, потому что у Figma нет ручки «покажи все мои
  файлы» (см. [Ограничения](#ограничения)).
- **Лог запросов** — кто из агентов что просил и сколько получил.

## Требования

- **Node.js 22+** (нужны встроенные `fetch`, `process.loadEnvFile` и `import.meta.dirname`).
  На Node 21.7+ тоже заработает, ниже — нет.
- Аккаунт Figma. Подойдёт бесплатный, кроме одной функции — см. Ограничения.

## Установка

```bash
git clone git@github.com:AIN427/figma-bridge.git
cd figma-bridge
cp .env.example .env
```

Создайте токен: **Figma → Settings → Security → Personal access tokens → Generate new token**.

**Снимите все права на запись.** Серверу нужно только чтение:

| Скоуп | Зачем |
|---|---|
| `file_content:read` | содержимое файлов и рендер картинок — главное |
| `file_metadata:read` | имя файла, версия, дата правки — проверка свежести кэша. Без него кэш навсегда остаётся `version unverified` |
| `current_user:read` | проверка токена ручкой `/me` |
| `folders:read` | обход командных проектов (необязательно) |
| `library_*:read` | имена стилей из подключённых библиотек (необязательно) |

Вставьте токен в `.env` и запускайте:

```bash
node server.js
```

Проверка:

```bash
curl http://127.0.0.1:3846/health
curl http://127.0.0.1:3846/me
```

Сервер слушает только `127.0.0.1` — наружу не торчит. `npm install` не нужен, зависимостей нет.

## Быстрый старт

Зарегистрируйте файл — достаточно ссылки из адресной строки Figma:

```bash
curl -X POST http://127.0.0.1:3846/files \
  -H "content-type: application/json" \
  -d '{"url":"https://www.figma.com/design/AbC123xyz/My-App","alias":"app"}'
```

Дальше на файл можно ссылаться как `app`, по ключу, по куску имени или полным URL:

```bash
curl "http://127.0.0.1:3846/f/app"                        # страницы
curl "http://127.0.0.1:3846/f/app/screens?q=login"        # найти экраны
curl "http://127.0.0.1:3846/f/app/find?text=Sign+in"      # найти по тексту на экране
curl "http://127.0.0.1:3846/f/app/screen/1:23"            # структура экрана
curl "http://127.0.0.1:3846/f/app/render?ids=1:23"        # PNG на диск
```

Первый запрос к файлу качает его целиком и может занять до минуты — дальше всё идёт
из кэша за миллисекунды.

## Ручки

Порядок — от дешёвых к дорогим. Смысл в том, чтобы спускаться по уровням, а не тянуть всё сразу.

**Диагностика:** `GET /health` · `GET /me` · `GET /log[?lines=40]` · `GET /` (справка из самого сервера)

### Что вообще есть

| Ручка | Отдаёт |
|---|---|
| `GET /files[?q=]` | реестр: файлы по проектам, с пометкой закэширован ли |
| `POST /files` | `{url\|key, alias?}` — зарегистрировать файл |
| `DELETE /files/:key` | забыть файл |
| `GET /discover?team=` | обойти команду и зарегистрировать все её файлы разом |
| `GET /search?q=&text=&type=[&fetch=1]` | поиск **по всем известным файлам** |
| `GET /projects?team=` · `GET /project/:id` | проекты команды · файлы проекта |

`/search` по умолчанию ищет только в уже скачанных файлах и в конце сообщает, какие
пропустил. `fetch=1` дотянет остальные — может быть долго, поэтому явно.

### Внутри файла

| Ручка | Отдаёт |
|---|---|
| `GET /f/:key` | имя, версия, страницы с числом экранов |
| `GET /f/:key/screens?page=&q=&limit=&offset=` | верхнеуровневые фреймы, строка на экран |
| `GET /f/:key/find?q=&text=&type=` | любая нода в файле: по имени, по тексту, по типу |
| `GET /f/:key/render?ids=&format=&scale=` | PNG или SVG **на диск**, возвращает пути |
| `GET /f/:key/screen/:node?detail=` | дерево экрана, детализация настраивается |
| `GET /f/:key/text?screen=:node` | все строки экрана |
| `GET /f/:key/node/:node` | одна нода сырым JSON |

Общие параметры: `refresh=1` — мимо кэша, `by=<имя>` — пометить себя в логе,
`json=1` — структурированный JSON вместо текста.

`json=1` отдаёт именно структуру, а не текст, завёрнутый в строку: тот же обход дерева
формирует оба представления. Ошибки в этом режиме тоже приходят объектом, с полем
`upstream` — сразу видно, кто отказал, Figma или сам сервер. Если структура не влезает
в потолок ответа, сервер вернёт `413` с объяснением, а не обрезанный и оттого
нечитаемый JSON.

### Детализация экрана

| `detail=` | Что добавляет |
|---|---|
| `outline` | дерево имён, типов и размеров (по умолчанию) |
| `layout` | + авто-лейаут, отступы, gap, выравнивание, constraints |
| `text` | + шрифты и сам текст |
| `style` | + заливки, обводки, радиусы, эффекты, имена стилей |
| `full` | всё сразу |

Поверх пресета: `include=layout,text,style`, `depth=N`, `maxNodes=N`.

Вывод — не JSON, а строка на ноду:

```
Subscription/Everything is ok  FRAME  375x954  fill=#1e202a  #19299:72260
  Payment information  FRAME  343x164  col gap8 pad16  r12  #19299:72265
    Payment method  TEXT  99x18  fill=#8b93a7  "Payment method"  #19299:72269
```

### Иконки в SVG

```bash
curl "http://127.0.0.1:3846/f/app/render?ids=13956:64937&format=svg"
```

Умолчания подобраны под иконки и переопределяются параметрами:
`svg_outline_text=false` (текст остаётся текстом, а не кривыми),
`svg_simplify_stroke=true` (чище обводка), `svg_include_id=false` (меньше мусора).
`scale` для вектора игнорируется.

## Как подключить к ИИ-агенту

Скопируйте [`AGENTS.md`](AGENTS.md) в свой проект под именем, которое читает ваш агент
(`CLAUDE.md`, `AGENTS.md`, `.cursorrules` — смотря чем пользуетесь). Там лежит порядок
работы, список ручек и грабли, на которые агент наступает без предупреждения.

Ходить агент может обычным `curl` — отдельная интеграция не нужна, и это дешевле, чем
MCP: описание ручек занимает контекст один раз, а не в каждом запросе.

## Почему это дёшево

Четыре решения, на которых всё держится. Если будете править — не сломайте их, это и есть смысл проекта.

1. **Кэш отделяет сеть от контекста.** Полный JSON файла тянется один раз в
   `.cache/<key>.json`, дальше все ручки режут по нему. Свежесть проверяется запросом
   `/files/:key/meta` по полю `version`, не чаще раза в 10 минут. Именно `/meta`, а не
   `?depth=1`: любое чтение `/files/:key` у Figma идёт по самому строгому лимиту (Tier 1,
   у мест View/Collab — месячная квота), а `/meta` — по лёгкому (Tier 3). Поверх дискового
   кэша — кэш в памяти на два файла: разбирать 167 МБ на каждый запрос это 3,9 секунды
   против 0,003 из памяти.
2. **Ответы — текст, а не JSON.** Строка на ноду вместо вложенных скобок: в 5–10 раз дешевле.
3. **Картинки отдаются путями, а не байтами.** PNG в контексте стоит ~1–1,5k токенов и
   обратно уже не выкидывается. Сервер кладёт файл на диск, а смотреть его или нет —
   решает агент.
4. **Потолки везде.** `maxNodes` на дерево, `limit` на поиск и на список экранов, потолок
   на любой ответ. Обрезка **всегда** сообщается отдельной строкой — молча не режем,
   иначе агент решит, что увидел всё.

## Как устроен код

```
server.js          вход: .env, HTTP-сервер, роутинг, лог, потолок ответа
routes/
  index.js         сборка таблицы маршрутов + контракт обработчика
  help.js          встроенная справка (GET /)
  diagnostics.js   /health /me /log
  files.js         реестр, /discover, /search, проекты команды
  file.js          всё внутри одного файла: /f/:key/*
  variables.js     POST /variables
src/
  errors.js        BadRequest (наша вина) и FigmaError (их вина) — раздельно
  figma-api.js     низкоуровневый клиент: авторизация, таймауты, типы ошибок
  rate-limit.js    что Figma сказала о лимите на 429 и последний отказ на диске
  cache.js         кэш на диске и в памяти, индекс нод, защита от гонок
  registry.js      files.json и разбор того, что ввёл пользователь
  images.js        рендер и экспорт на диск
  format.js        компактные представления дерева
test/              node:test, без зависимостей
```

Обработчик маршрута возвращает либо строку, либо `{ text, data }`. Оба представления
строятся за один обход — поэтому `json=1` не может разойтись с текстовым выводом.

## Тесты

```bash
npm test
```

Встроенный `node:test`, никаких зависимостей. Покрыто то, что ломается молча: обход
дерева с ограничениями по глубине и количеству, отчёт об обрезке, поиск по тексту,
разбор пользовательского ввода в ключ файла и то, что ошибки валидации не выдают себя
за ошибки Figma.

## Ограничения

Честно, чтобы не было сюрпризов.

**Нельзя получить список всех своих файлов.** У Figma REST API такой ручки нет. Есть
«проекты команды» и «файлы проекта», а файлы в **Drafts не перечисляются вообще**.
Поэтому у сервера свой реестр `files.json`: командные файлы забираются одной командой
`/discover?team=`, а всё остальное добавляется по ссылке через `POST /files`. Пустой
реестр сервер не молчит, а объясняет, что делать.

**Имена переменных недоступны вне Enterprise.** Figma Variables REST API открыт только
на Enterprise-тарифе. На остальных связанная переменная показывается как `var:?`.
Имена **стилей** отдаются на любом тарифе. Если у вас есть свой способ достать карту
переменных (например, плагин, который читает их изнутри Figma), скормите её серверу:

```bash
curl -X POST http://127.0.0.1:3846/variables \
  -H "content-type: application/json" \
  -d '{"fileKey":"AbC123xyz","variables":{"VariableID:1:2":"Background/2"}}'
```

Дальше имена начнут подставляться в `detail=style`.

**Рейт-лимит общий на токен** и выбирается несложно. Сервер это переживает: при `429`
ответ всё равно придёт — из кэша, с пометкой `version unverified` или `STALE` в первой
строке. Пометку надо читать: она значит, что свежесть данных не подтверждена.
Когда Figma отказывает по лимиту, сервер передаёт её заголовки: сколько ждать
(`Retry-After`), тип лимита (`low` — место View/Collab, `high` — Full/Dev), тариф и ссылку
на повышение. Последний отказ хранится в `.cache/rate-limit.json` и виден в `GET /health`
без нового запроса к Figma. Как это читать агенту — в [AGENTS.md](AGENTS.md).
Экспорт картинок кэшем не покрывается, поэтому большие пачки иконок шлите одним вызовом
со списком id, а не циклом по одной.

**Разбор очень большого файла подвешивает сервер на несколько секунд.** `JSON.parse`
на 167 МБ блокирует единственный поток Node, и в это время сервер не отвечает никому.
Происходит один раз на файл — дальше всё идёт из памяти. Чинится только выносом в
worker-поток, и для локального инструмента на одного пользователя это не окупается.
По той же причине в памяти держатся максимум два файла: каждый стоит реального хипа.

**Импорт `.fig` из чужого аккаунта рвёт связь с командной библиотекой.** Часть стилей
после такого импорта схлопывается в голые хексы вместо имён. Это не баг сервера, так
устроен импорт.

## Безопасность

- Токен — только на чтение. Через сервер физически нельзя изменить макет.
- `.env`, `.cache/` и `files.json` в `.gitignore`. **Не убирайте их оттуда:**
  в кэше лежат чужие макеты и рендеры, в реестре — ключи чужих Figma-файлов.
- Сервер слушает `127.0.0.1` намеренно. Не выставляйте наружу: он ходит в Figma вашим
  токеном и не спрашивает, кто его дёргает.
